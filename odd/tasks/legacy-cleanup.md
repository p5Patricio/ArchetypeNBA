# Feature: legacy-cleanup

## Objective
Safely remove pre-PostgreSQL prototype files from the repository root and `backend/`, migrate still-used report generation code into `backend/app/services/scouting_report/`, keep active data files and ETL pipelines intact, and ensure all tests and references are clean without dangling links.

## Problem
The repository root still carried files from the pre-PostgreSQL prototype:
- `api.py` (standalone prototype FastAPI app)
- `nba_data_processor.py` (root and `backend/`)
- `nba_player_analyzer.py` (root and `backend/`)
- `nba_player_data.py` (root and `backend/`)
- Tracked `.pyc` files in `__pycache__/` and `backend/__pycache__/`
- `cluster_means_report.xlsx` (an output artifact from running `nba_data_processor.py`)
- `app/__init__.py` (root `app/` directory)

Removal had been postponed because `backend/app/services/report.py` imported from `nba_player_analyzer`, and `seed_database.py`/`data_update.py` depend on `backend/app/etl/pipeline.py` and the `nba_active_player_stats_*.xlsx` data files.

## Why
Dead code, confusing duplicates between root and `backend/`, and non-package imports (`from nba_player_analyzer import ...`) create confusion, risk accidental imports of stale code, and violate clean architectural boundaries.

## Scope
- Complete inventory of all legacy files, their importers, and readers across the codebase.
- Extract the report generation logic needed by `report.py` (`generate_player_report_pdf`, `create_radar_chart_to_file`, `STAT_NAMES_MAP`, `radar_stats_categories`, `assign_cluster_roles`) into a clean module `backend/app/services/scouting_report/`.
- Add comprehensive offline tests for `ReportService` and `GET /api/v1/player/{player_name}/report`.
- Remove dead legacy files that have zero remaining users: `api.py`, `nba_player_data.py`, `nba_data_processor.py`, `nba_player_analyzer.py`, tracked `.pyc` files, `cluster_means_report.xlsx`, and root `app/`.
- Preserve `backend/app/etl/pipeline.py`, `backend/scripts/seed_database.py`, `backend/app/services/data_update.py`, and the three `nba_active_player_stats_*.xlsx` data files.
- Update documentation: `README.md`, `AGENTS.md` (sections 4 and 8), `docs/ARCHITECTURE.md`, and `docs/ROADMAP.md` (mark item 10 done).

## Constraints
- Paper trading only, free tiers only, never fabricate data.
- Offline and deterministic tests (in-memory SQLite, no network).
- Zero schema changes (no Alembic migrations).
- Do NOT delete data files that any code path opens (`nba_active_player_stats_*.xlsx`).
- Work strictly inside the worktree (`wp-legacy`).
